## 0. Цель и мерки (согласовать до старта)

Цель пользователя: на фиксированном наборе знаменитостей **≥ 95 %** по двум мерам, обе — независимым распознавателем, который не участвует в обучении.

| Мера | Что значит | Сейчас (baseline) | Цель |
|---|---|---|---|
| **Узнавание** | рендер ближе всего к снимку своего человека среди набора; доля «1-е место» | 8/24 (~33 %) по cos; 2/24 по face-api | ≥ 95 % |
| **Верификация** | расстояние рендер↔снимок ниже порога «тот же человек» | 0 % (порог ~0,6, сейчас 0,664) | ≥ 95 % — **не обещаем**, см. риски |
| **Причёска** | IoU силуэта волос | 0,457 | не хуже 0,43 (гейт падает при −0,03) |

Решения, которые надо принять пользователю до начала:
- [ ] Подтвердить формулировку «95 %»: узнавание, верификация или обе.
- [ ] Размер набора знаменитостей (предложение: 24 — текущий набор + 40 новых, итого ~60 лиц, с разбиением «обучение / проверка» 50/50).
- [ ] Допустимо ли, что проверочный распознаватель отличается от обучающего (предложение: да, face-api для проверки, ArcFace-подобный для обучения).

### Выводы

1. **Коммерческий путь без внешних весов по геометрии возможен только двумя способами:**
   - FLAME 2023 Open (CC BY 4.0) как база 3DMM, если его пространство форм годится;
   - собственный регрессор на наших рендерах, без FLAME и BFM.
2. **Регрессор на эмбеддингах ArcFace (buffalo_l) — юридически спорный.** Если его обучать на эмбеддингах модели с некоммерческой лицензией, а веса шипить в npm, это может считаться производным от этих весов. Варианты: (a) получить коммерческую лицензию InsightFace; (b) обучать на эмбеддингах распознавателя, который можно коммерчески (MediaPipe-подобного или собственного); (c) не шипить регрессор, а держать его на сервере. Решение — за пользователем и юристом.
3. **Измеритель (гейт, dev) не равен продукту.** Для гейта можно использовать и некоммерческие веса (buffalo_l, DECA/MICA-подобные), если они не попадают в npm и не в поставку. Тогда ни одна метрика не ограничивает продукт, но и продукт не должен из них что-либо брать.
4. **face-api в продукте — нельзя, пока не выяснена лицензия весов.** Сейчас он только в dev.
5. **Набор знаменитостей:** снимки — чужой контент. Внутри проекта для измерения допустимо локально; публиковать и шипить — нет.

## 2. Пробы потолка (полдня–день каждая, до любой крупной работы)

Каждая проба — с критерием «идём / не идём» записанным заранее.

- [ ] **P1. Потолок узнавания.** Два разных снимка одного человека из набора: какое расстояние и место даёт face-api. Это верхняя граница, выше которой не прыгнуть.
  - Идём дальше, если верхняя граница ≥ 0,35 по распознаванию (иначе сравнивать не с чем — проверить сам набор и качество снимков).
- [ ] **P2. Фото на реалистичной голове.** Текстура на весь овал, `realism: 1`, шарж 0, без 14.1–14.7. Узнаётся ли?
  - Если да → сначала текстура (пункт 4.3), геометрия потом.
  - Если нет → геометрия — основной путь (3DMM или синтетический регрессор).
- [ ] **P3. Сигнал «эмбеддинг → параметры».** 2–3 тыс. синтетических рендеров, маленький MLP, отложенная выборка. Есть ли корреляция предсказанных мерок с истинными и растёт ли узнавание по сравнению с текущим fit()?
  - Идём дальше, если на отложенной выборке узнавание лучше текущего хотя бы на 15 процентных пунктов.

Результаты проб записываем сюда же, с числами и путями к dev-скриптам.

## 3. Основной путь: синтетический регрессор (MICA-подобный, на нашей голове)

Идея: эмбеддинг распознавателя → параметры нашей головы, обучение на данных, которые мы сами рендерим.

### 3.1 Данные
- [ ] Схема параметров: какие поля `look`/`PhotoOptions` входят (мерки `TUNE`, `widths`, `noseSize`, `chinSize`, `dome`, глаза, губы; без волос и текстуры). Фиксируем список в одном месте.
- [ ] Сэмплер: равномерно внутри разумных диапазонов + выборка около среднего лица (60/40). Без шаржа.
- [ ] Рендер анфас в той же камере, что `_shotFace` (`_faceCam`), без очков и бороды (как в 14.6 на рендере).
- [ ] Эмбеддинг каждого рендера тем же распознавателем, что на фото.
- [ ] Объём: 2–3 тыс. (P3), затем 50–100 тыс. (после P3).
- [ ] Время: на swiftshader ~2 с/кадр → 100 тыс. = несколько дней на CPU. Нужна GPU-машина или батч-рендер без `readPixels` на каждый кадр (уточнить).
- [ ] Хранение: `dev/synth/` (в `.gitignore`), манифест с seed и параметрами.

### 3.2 Модель
- [ ] Вход: эмбеддинг (512-мерный ArcFace-подобный или face-api, решить после P1).
- [ ] Выход: вектор параметров (пункт 3.1).
- [ ] Архитектура: MLP 2–3 слоя, dropout, нормировка. Не сложнее.
- [ ] Потери: MSE в σ (разброс черт из `MEAS_POP`), плюс потеря на эмбеддинге — `1 − cos(emb(render(θ̂)), emb(photo))` на подмножестве (дифференцируемый рендер не нужен на первом шаге).
- [ ] Обучение в Python (dev-скрипт), экспорт весов в JSON или ONNX; инференс в браузере — на MLP это несколько мс.

### 3.3 Интеграция
- [ ] Предсказание из эмбеддинга фото → стартовые мерки **до** `fit()`; дальше — текущий путь (шарж, поправки 14.6, точки 14.7 поверх).
- [ ] Флаг `look.regress` / `photoOptions.regress`, по умолчанию **выключен**, пока не выиграет гейт (правило: новый дефолт должен выиграть гейт, иначе opt-in).
- [ ] Поля в файле аватара: `v2` с признаками модели; `v1` импортируется как раньше.
- [ ] Совместимость: кэш `fit()` учитывает версию модели.

### 3.4 Оценка
- [ ] Held-out: 50 % набора знаменитостей не участвует ни в обучении, ни в подборе порогов.
- [ ] Проверка двумя распознавателями: если обучали на ArcFace-подобном, мерить face-api (и наоборот).
- [ ] Визуальные тесты не меняются (регрессор выключен по умолчанию).

## 6. Риски (известные)

- **Разрыв рендер ↔ фото.** Распознаватель на рендере мультяшной головы может видеть другого человека. Мерить тем же распознавателем, которым мерим сейчас.
- **Обман распознавателя.** Оптимизация под одну модель даёт рост на ней и падение на другой. Всегда две модели.
- **Потолок верификации.** 95 % «тот же человек» не обещаем: даже 3DMM-продукты на этом не выходят стабильно.
- **Лицензии.** Блокер для пунктов 4.1, 4.4 и для весов в npm.
- **Стиль.** Больше сходства ≠ больше реализма: риск «зловещей долины» (см. ROADMAP, «Риски»).
- **Стабильность рига.** Геометрия по регрессору не должна ломать морфы и веки (см. ROADMAP, «Риски»).
- **Производительность.** Инференс MLP дешёвый, но генерация 100 тыс. рендеров — дни на CPU.
